# Operator Phase 8A.4A — Cloud worker authority (non-billable foundation)

Compatible with HomeServer PR #376's signed registration request/response format and #377's transport-only boundary. No changes to LiveKit or existing phone calls. Only session.simulate and session.recover are accepted. Real execution and live certification remain false.

The isolated PHP class accepts a trusted server-side inventory of independently scoped credentials. This is not a provisioning service or HTTP endpoint. Never supply credentials from request data, reuse the HomeServer pairing token or Twilio secret, log the inventory, or use fixture keys outside tests. Explicit installation creates only metadata tables; no existing setup/upgrade or public route is changed. A short transactional database mutex serializes registration, replay receipts, boot fencing, selection, synthetic reservation, completion and durable revocation across connections. The fixed registration lifetime is 90 seconds. Exact retries do not refresh it. Rotation requires explicit durable revocation. Registration or selection is never permission to call.

Owner-scoped selection prefers a fresh idle HomeServer, then a fresh idle provisioned Cloud worker, then latest heartbeat and credential ID as deterministic tie-breaks. Claims are simulation-only, have a maximum 30-second lifetime, bind credential/boot/generation, and reserve one occurrence and one worker. Expiry, revocation, retirement, lost capability or generation mismatch produce an uncertain terminal occurrence; no automatic retry of that occurrence. Duplicate requests return state only. An available worker may process a different synthetic occurrence; this does NOT establish safety for a second physical phone call.

Run php tests/agent-operator-worker-authority-8a4.php against SQLite and the dedicated MySQL CI database. The fixed public HMAC vector matches the Python protocol. CI covers validation, duplicate receipts, clock, owner separation, priority, occupancy, fencing and retirement. A separate process race test competes on registration and claims using the same durable SQLite/MySQL store. Further gates: paired-account credential provisioning/rotation and revocation wiring, authenticated capped HTTPS endpoint, pinned HomeServer client exchange, independent recipient consent and contact/line/schedule policy, authoritative live claims/renewals and uncertain-carrier reconciliation, production multi-host acceptance, worker deployment and physical calling tests. Do not enable execution until those gates pass.
