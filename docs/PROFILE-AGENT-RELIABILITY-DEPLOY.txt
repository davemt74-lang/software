Profile Agent and Messages reliability release — deployment and acceptance

INSTALL
1. Deploy the reviewed release through the normal Cloud update process.
   Preserve config.php, .env, private/ and uploads/.
2. Sign in as an administrator and run Database Upgrade (upgrade.php).
   The new tables are profile_phone_settings_v1 (optional public-line approval),
   profile_agent_response_settings_v1 (owner response mode),
   profile_agent_owner_requests_v1 (durable requests for owner input), and
   profile_agent_knowledge_saves_v1 (reviewed answer filing receipts),
   profile_browser_phone_calls_v1 (visitor-bound browser calls), and
   profile_browser_phone_cancellations_v1 (canceled call requests).
   Fresh setup.php installs them too. Public reads never install schema.
   Upgrade completeness includes these tables; existing Phone or Knowledge
   setup alone does not mean the Profile additions are installed.
3. Refresh Profile, Profile Agent, and Messages after deployment. Changed assets
   use content-based versions. Browser history restoration rechecks the current
   account/visitor rather than keeping stale private state.

RESPONSE MODES AND EXISTING KNOWLEDGE ACCESS
4. In Profile Agent > Agent, choose Automated or User responses. Existing
   installations retain Automated unless the owner changes it. User responses
   submits each text question directly to the owner without model inference.
   Automated uses permitted knowledge and submits the question if it cannot
   answer. Both submission paths show a saved submitted/waiting Status receipt.
5. Verify the owner request in Inbox and the existing Main Chat visitor card.
   Waiting must not claim a live owner connection. Reply, resolve, or explicitly
   return to Agent using the existing conversation controls. User responses
   cannot be bypassed by a visitor's stale Agent choice or an old browser tab.
6. After replying, choose Save to Knowledge beside the owner message. Review
   the title/content and choose an existing personal Knowledge folder. Saving
   is deliberate, and it never changes Profile Knowledge access or audience.
   Use the existing Profile Agent > Knowledge Access > Knowledge Base Allow
   and audience controls to manage use, along with any existing item/Agent
   rules. With Knowledge access disabled, a newly saved answer must remain
   unavailable to visitors. Existing visibility does not expose an unpublished
   personal note on its own. Open the saved note in My Knowledge for later edits.

PUBLIC TWILIO PHONE CALLING
7. Keep the current tested Twilio setup and signed incoming callbacks. Assign
   the line to an active Agent belonging to the owner, enable incoming voice,
   and ensure the owner has the existing Phone number and voice allowances.
   Browser answering, voicemail, fallback and recording remain configured in
   the existing Phone workspace. See CLOUD-PHONE-WORKSPACE-DEPLOY.txt.
   For Call in browser, configure the existing same-account API Key SID/Secret
   and TwiML App SID in Admin > Phone and enable browser calling for the line.
   The TwiML App Voice Request URL is the configured HTTPS installation's
   /api/phone-browser-voice-v1.php (POST). Set its Voice Status Callback to
   /api/phone-browser-status-v1.php (POST, without a call query parameter).
   Keep the number's existing /api/phone-voice-inbound-v130.php callback and
   the generated child-leg callback query parameters unchanged.
8. Open Profile Agent > Agent > Profile phone calls. Select the eligible assigned
   Twilio line and enable Show Call by phone in my Profile chat. Save.
   Publication defaults to off. The selected number becomes public; personal
   callback details remain private. Number reassignment revokes publication,
   even if the line later returns to the same owner.
9. Call in browser requests microphone permission after the visitor clicks,
   connects using the bundled Twilio SDK and shows ringing/route, mute and hangup
   controls in the widget. Call by phone remains the native phone-app option.
   A changed number requires another click. Existing native Profile audio/video
   remains separate; simultaneous owner calls and microphone use are prevented.
   An SDK connection does not prove the owner answered. The UI distinguishes
   owner pickup from the configured Phone Agent and voicemail. A Phone call
   does not join the owner to live text chat; other drafts are retained.
10. Calls follow the line's existing browser-owner, supported Cloud Phone Agent
    or voicemail route. The Phone Agent keeps its existing phone-only scope;
    it is not automatically granted the Profile text or personal Knowledge.
    The current HomeServer SIP bridge requires a carrier caller number, so
    anonymous SDK calls use the supported browser/Cloud/voicemail fallback.
    Signed carrier outcomes are tied to the exact Profile conversation and
    appear as Status receipts. Existing native call report totals stay native;
    Twilio activity/recording reports remain in Phone. A phone-app click alone
    is not a connected-call receipt.

ACCEPTANCE
11. From a separate visitor browser, open the Profile, send a message, and check
   the owner Inbox and Main Chat visitor card. Check an anonymous return after
   logout and confirm a relevant visit/announcement without duplicate entries.
   Test Available, Away and DND with the intended speech settings. A running
   HomeServer alone does not establish owner availability.
12. Test live owner pickup within the offer window, missed-offer Agent fallback,
   and Inbox Take over / Let Agent handle / Resolve. Confirm owner takeover
   prevents a late competing Agent answer in the same conversation.
13. Test both response modes with known and unknown information. For User
    responses, verify no Agent answer precedes the waiting receipt. For Automated,
    verify a supported answer and an actual submitted request for missing facts.
    Send two questions while the Agent is running; every handed-off question
    must have its own request. Reply to an earlier question and confirm newer
    pending questions remain. Changing modes or taking over must suppress an
    obsolete running Agent reply. Signed external callers follow the same rules.
14. Save an answered request into an existing Knowledge folder. Confirm one
    ordinary note, no duplicate after a lost-response retry, no automatic save
    from the reply alone, and no changes to Knowledge Access. Check retrieval
    under the intended Allow/audience and after revoking it. Save an older answer
    while a newer question waits; select the correct question when one reply
    covers several requests. No visitor should receive owner Knowledge actions.
15. In Messages, verify two-account exchange, pending request acceptance, new
    replies in a thread longer than 120 messages, Load earlier, exact deep links,
    and phone-width navigation. Switch accounts in another tab: the old Messages
    page must clear and require reload, including its Shares actions.
16. In Profile image settings, approve a free reference collection. Test subject
    upload, edit, download and a revision with the configured image provider.
    Verify private owner preview separately. Provider calls consume the existing
    allowances; the source audit used controlled provider responses only.
    Check free renders remaining before/after an edit and revision, zero at the
    limit, UTC-day reset information, and unknown when allowance cannot be read.
    A returning guest must keep the existing allowance rather than see a fresh
    full balance. Failed/cancelled admissions retain the existing counting rule.
17. Open the Profile specialist report, select a completed local period, and
    inspect visit/chat/call/commerce/image measures and coverage. Keep unavailable
    evidence distinct from zero, and recorded conversion value distinct from
    verified payment receipts. Refresh stalled reads rather than assuming zero.
    Check Owner responses for submitted/answered questions, separate gap/direct/
    service/allowance reasons, and median/90th-percentile verified reply delay.
    Current owner requests show waiting/delegated counts, oldest questions,
    current waiting time, recurring gaps and exact conversation links.
    Review suggested existing notes in My Knowledge. These are keyword matches
    for review, not automatic edits or permission changes. Revoke a note's
    current Agent access and verify its suggestion disappears. Old unproven
    original reasons and unavailable sources must remain marked unknown.
18. With an explicitly enabled test phone line, place a real call from the chat
    widget and verify microphone permission, owner ringing/pickup, mute, hangup,
    missed pickup, configured Agent/voicemail fallback, and existing recording
    behavior. Test the phone-app option separately. Check the conversation receipt
    and Phone history. Deny microphone permission and confirm no redial occurs.
    Close the widget or switch account and confirm microphone capture stops.
    Cancel while preparation is pending; no late response should start a call.
    Disable publication and confirm the next read removes the action and stops
    a current visitor call. Agent work resumes only after a confirmed end and
    under the saved Automated/User responses and explicit pause settings.

RECOVERY
19. Read failures expose retry/reload controls. After an uncertain settings or
    other mutation response, reload and inspect saved state before resubmitting.
    A stale account page must reload; it cannot reuse old conversation authority.
20. Disabling Profile phone publication removes the public actions. The widget
    rechecks authority during a call; existing assignments and historical records
    remain. A missing completion callback is reconciled against the exact carrier
    call, at most every 30 seconds during status/recovery or a later call attempt.
    Authenticated owner Phone/native call views also perform that recovery after
    public calling is disabled. If the Twilio account itself has changed, the
    old account's remaining call must be checked with that account's credentials.
    Unknown provider state keeps the reservation held. Check Twilio connectivity
    and the fixed status callback before retrying; do not delete the tables or
    provider records as a routine rollback. Public owner Dial legs have a 600-second
    bound and later public routing is fenced at ten minutes.
