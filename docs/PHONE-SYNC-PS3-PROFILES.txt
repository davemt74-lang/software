# Phone Sync PS3 — connected-user profiles in Phone Tracking

The existing map, approved-device list and selected-phone panel are the canonical workspace. Each selected phone has communication, permission and activity sections. Current location, camera, chat, history and saved-place controls use their existing authorities; new shortcuts reuse the actual history/places tabs. No duplicate contacts list or map. The phone holder edits their own number and future communication preferences in the paired phone app. The owner sees a masked number only. The QR pairing ID anchors the profile; a separate random profile identifier remains stable across GPS generation and phone-number changes. Re-pairing creates a new relationship; cross-device identity linking is a future feature.

Account approval is not call consent. Independent owner and holder permission, number revision, proactive opt-in, timezone/window, daily maximum and minimum gap are saved. Changing the number clears call consent. Revoking an owner grant clears holder consent. Pending, expired, revoked or foreign connections cannot save preferences. Disconnect deletes the profile; expiry is excluded from reads and normal pairing cleanup removes expired records. No new number in Chat or model context. No phone-number verification code. Future calling must still check the exact current pairing, number, both permissions, line, quiet hours, budgets and applicable consent.

No carrier dispatch, new number purchase, app calling, AI memory retention, new data requests, push service or automated outreach is enabled. The UI labels these preferences and planned services accurately. Cloud upgrade adds the profile table through the existing phone schema installer. Tests use SQLite/MySQL and isolated QR pairings, not actual phone data.
