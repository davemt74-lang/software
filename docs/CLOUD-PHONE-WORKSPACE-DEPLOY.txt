VP3 Cloud Phone Workspace — deployment and acceptance

This release adds a member phone drawer, Twilio browser calling, call cards in
private Agent Chat, owner-private voicemail playback and callback controls,
favorites from existing CRM contacts, and optional recorded-call transcription
and reports. Core browser calls use Twilio directly. They do not require
LiveKit or a HomeServer installation. The separate Phone Tracking, paired-phone
camera and location applications are not the telephone feature.

INSTALL
1. Extract the verified Cloud deployment ZIP over the existing Cloud source.
   Preserve config.php, .env, private/ and uploads/.
2. Sign in as an administrator and run upgrade.php. It installs phone workspace,
   recording, speech-budget and historical SMS ownership migration storage.
   Owner voicemail controls additionally install per-line preferences, private
   greeting bytes, short-lived call-bound greeting grants, consent receipts and
   durable deletion tombstones. Run the upgrade even if older Phone calls work.
   A partial voicemail upgrade leaves Connections, Contacts and Recent calls
   available while Voicemail requests the database upgrade.
   It also enables shared CRM contacts with a name and phone number and no email.
   Run this upgrade before using Add to contacts in a call card or active-call panel.
   Existing assignments remain unchanged. Fresh setup.php installs the same schema.
3. Open Admin > Phone & Messaging. Keep the tested Twilio Account SID/Auth Token
   and existing number assignment. An actual number must belong to an active
   Agent owned by that member. Unassigned members get no phone entry point.

SUBSCRIPTION AND ADMIN ACCESS
4. Admin > Subscription packages sets the recurring monthly package price.
   Enable Agent Phone Numbers Included (phone.numbers), with an explicit positive
   quantity, and Agent Phone Calls (phone.voice). Existing package billing and
   subscription lifecycle remain authoritative; this release does not choose a
   price, create customer subscriptions or charge a customer on deployment.
5. For a complimentary/admin override, use Admin > Entitlement Grants. Grant a
   positive phone.numbers quantity and phone.voice, with a reason and optional
   expiry. Existing grants compose with the package and can be revoked. A grant
   still requires an administrator-assigned number. Assignment alone does not
   bypass package/grant calling entitlements. Expired/revoked access prevents new
   paid phone actions and processing. Existing owner-private records retain their
   original owner when numbers are reassigned.

TWILIO BROWSER SETUP
6. Under Browser phone, save a Twilio API Key SID, API Key Secret and TwiML App
   SID from the same Twilio account as the assigned number. Account SID/Auth Token
   alone cannot mint browser Voice access tokens. Secrets are encrypted at rest
   and are never sent to the browser.
7. Set that TwiML App's Voice Request URL to the exact POST URL displayed in
   Admin > Phone. It ends in /api/phone-browser-voice-v1.php. Keep the number's
   existing signed incoming callback /api/phone-voice-inbound-v130.php.
   Public HTTPS and Twilio access to these URLs are required. Do not rewrite or
   remove the signature-checked callback query parameters.
8. Enable incoming voice, then enable browser calling for the assigned number.
   Enable recording only if desired: the per-number setting records incoming
   browser calls and permits recording outgoing calls. The member separately chooses
   Record this call for an outgoing call. Recorded calls play a spoken notice to
   the called party before connecting. Existing voicemail has its own greeting.
9. The member opens Agent Chat, clicks the header phone icon and enables calls.
   After updating an existing installation, refresh Chat and enable browser calls
   again so the browser registers the current Voice identity.
   Browser microphone permission is needed when accepting or placing a call.
   The existing microphone ownership lease prevents competing voice surfaces.
   The phone rings in the compatible owner Chat Agent scope; an unavailable owner
   follows the existing voicemail/AI fallback. Browser calling does not require
   the separately configured LiveKit/HomeServer streaming bridge.

AUTOMATIC TRANSCRIPTS AND REPORTS
10. Add a once-per-minute hosting cron job, using the installed PHP CLI binary
    and full installation path:
      * * * * * php /full/path/to/vp3/phone-recording-worker-v1.php
    On cPanel, select Once Per Minute and enter the command portion only.
    Use the hosting account's PHP CLI matching the Cloud PHP version/extensions.
    This dedicated worker processes one recording per invocation; a private
    nonblocking lock prevents overlap. It keeps speech jobs off the shared Agent
    worker. Signed webhooks enqueue metadata and never run speech inline.
11. In the member phone's After calls settings, explicitly enable Cloud processing
    and choose retained audio, transcripts and report sections. Defaults do not
    automatically send recordings to speech or AI providers. Transcription uses
    the configured Cloud speech service; report analysis uses existing Cloud model
    routing and AI quotas. Speech-provider usage is separate from LLM token usage.
    Automatic speech has a 60-minute/hour owner ceiling, 25 MB media bound and
    one-hour per-recording ceiling. Uncertain paid requests require review before
    retry, so a lost response is not automatically charged twice.
12. Reports use existing Summary, Questions, Actions, Decisions and Follow-up
    modules. Transcripts are private canonical drafts. The worker posts a report
    to owner Chat; it does not send a callback, publish a transcript or accept
    suggested actions automatically. Server worker observation means only that
    the process ran; the UI does not claim a provider was verified by that signal.

OWNER VOICEMAIL CONTROLS
13. Open Phone > Voicemail in the owner's private Chat workspace. Each assigned
    number has independent preferences. Choose 2–10 approximate rings; the UI
    also shows the estimated 12–60 seconds. Twilio's Dial timeout includes an
    additional five-second buffer, which the incoming browser timeout accounts
    for. Carrier ringback cadence varies, so an exact ring count is not promised.
    When browser calling is unavailable, the existing fallback can answer at once.
    Outgoing calls and managed call/disclosure flows retain their existing timing.
14. Select Record greeting, permit the microphone, then Stop and preview it.
    Save greeting is a separate action; an unsaved recording is discarded when
    leaving the tab, closing Phone or changing Chat/number. Greetings are 1–60
    seconds of mono 16 kHz PCM audio and use the existing microphone ownership
    lease. Use standard greeting removes the saved personal greeting. Callers
    still hear the recording notice before the voicemail Record instruction.
    Greeting preview requires the private owner session. Carrier playback uses
    a short-lived grant bound to the current incoming call and greeting; changing
    the greeting or number assignment invalidates that grant.
15. Automatic voicemail transcription starts off. Enable it per number, or use
    Transcribe voicemail on an individual existing message. Both use the same
    phone-recording-worker-v1.php cron command in step 10 and existing speech
    quotas; no new scheduler is required. Voicemail does not enable call recording
    or automatic call analysis. The worker observation appears next to these
    settings so an unobserved/stale worker is not mistaken for finished work.
16. Post new voicemail in Agent Chat controls automatic text announcements and
    saved transcript reports. Their original caller and call receipt are retained;
    an existing incoming Agent conversation is reused. Post voicemail to Chat
    explicitly posts the saved message/transcript in the current private Chat.
    Reports are deduplicated. These are ordinary assistant text posts with Phone
    cards; they do not start a new text-to-speech path or place a call.
17. Delete voicemail requires an in-card confirmation. It revokes playback,
    discards its canonical transcript/audio, and replaces its related Phone posts
    in Chat with Voice message deleted. Durable tombstones fence duplicate carrier
    callbacks and late workers. The existing worker retries private file cleanup
    and the authenticated provider DELETE until confirmed. Deleting voicemail
    does not delete separate call recordings or other owners' records.

RELEASE VALIDATION
Automated checks cover actual PHP/SQLite state projections, isolated MySQL
persistence/migrations, signed carrier callbacks, single-use dial intent replay,
Agent/owner boundaries, disclosure ordering, out-of-order callbacks, typed legacy
and new voicemail identities, private playback, recording/transcript persistence,
policy/assignment revocation between paid requests, budgets, UI/media races,
responsive screenshots and the pinned unmodified Twilio JavaScript SDK.
No test calls or customer billing changes are made by deployment or CI.

SITE ACCEPTANCE
After configuring the deployed site, verify an incoming call with Accept/Decline,
an outgoing call, muted audio and hang-up, voicemail playback plus Call back,
an explicitly recorded call with audible notice, and the worker-created transcript
and report. Save a caller with Add to contacts and confirm its name and number
appear in Contacts, call history and SMS history. Confirm an unassigned user has
no phone icon and cannot call its APIs.
Confirm paid package access and an explicit admin grant both work only alongside
a real assignment, and that removing the allowance blocks a new call. Carrier,
real microphone/audio quality and production credentials need this live check.
For voicemail, save and preview a personal greeting, call the assigned number
with the browser available and unavailable, verify the estimated timeout and
spoken recording notice, leave a message, transcribe it, inspect the correct Chat,
then delete it and verify playback/transcript/Chat redaction and provider cleanup.
Check the same flow on a physical iPhone. Automated browser and injected-carrier
checks do not establish hosted microphone quality or live carrier acceptance.

Operator scheduled call occurrences
  To check up to 100 currently due, prepared calls without dialing or consuming
  an occurrence, run: php phone-operator-schedule-worker.php --preview-dispatch
  The output contains counts by reason. An eligible result means the current
  route, consent, known browser call history, Calendar and calling hours passed
  rehearsal. It does not reserve a call or submit anything to Twilio.
  After running upgrade.php, configure the Cloud scheduler to run the CLI worker each minute:
      * * * * * php /full/path/to/vp3/phone-operator-schedule-worker.php
  Only explicitly assigned Calendar call series are considered. Open Phone > Contacts >
  Scheduled calls to see the last occurrence and its preparation status. Prepared means
  the scheduled time arrived and the preliminary line and recipient checks passed.
  The default command prepares calls and delivers outcomes to the original Agent Chat.
  To place scheduled calls when the browser is closed, add --dispatch to that same cron
  command after configuring the assigned Twilio line, public HTTPS callbacks, recording
  worker and the owner and recipient permissions. Remove --dispatch to stop new submissions.
  In Agent Chat, open ddd and inspect Operator > Scheduled call worker. Check the last
  run time, outcome and whether that run allowed dialing. A preparation-only run leaves
  calls undialed. A preview leaves this status untouched. Older runs can show mode unknown.
  The recipient hears the recording and transcription disclosure and chooses whether to
  continue. An uncertain carrier receipt counts as an error and retains its reservation.
  When the connected-phone holder has enabled call memory, the Agent may receive up to
  four saved turns from earlier calls in the same Calendar series, contact, private Chat
  and Agent scope. Changing that memory grant while a reply is being generated discards
  the reply. Disabling memory removes prior turns from later model requests.
  Check the original call history and the carrier log before taking further action.
