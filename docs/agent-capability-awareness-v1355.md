# Capability awareness — Section 1

The Cloud Chat runtime now constructs a server-derived capability snapshot for each owner turn. The ordinary typed, spoken, streaming and legacy Chat paths initialize the same snapshot. Provider system instructions use it after the legacy descriptive catalog, so historical claims and page data cannot redefine current access. Public Profile Agent prompts remain separate.

The first inventory covers reminders, calendar reads/changes, personal Knowledge search, Brain recall, shared-screen discussion and HomeServer discovery. It distinguishes permission denial, missing installation, required upgrade, failed readiness check, disabled/unavailable scope, required screen sharing and unchecked HomeServer connectivity. Inventory presence is descriptive only; all existing executor authorization remains in force. Unlisted capabilities are unassessed, not declared unsupported. No capability data is persisted in Chat or the database. No migration or new management UI.

Validation: 26 cases cover ready/empty versus blocked, changed permissions, folder ownership, project isolation, stale snapshots, failed probes, forged/expired screen context, cross-account isolation, public Profile Agent exclusion and existing provider prompt integration. Recovery Baseline is the merge gate.

Next sections add LLM-selected conversational discovery and authenticated HomeServer inspection, then execution diagnostics and inventory coverage checks. HomeServer source stays unpublished.
