# Operator — owner phone possession verification

Account > Phone & Agent Calls can request and check a dedicated Twilio Verify SMS challenge. The feature is off by default. Configure private config.php operator_owner_phone_verify with an explicit enabled flag, exact AC account, dedicated VA service (10-minute SMS code lifetime, Fraud Guard and appropriate geographic/usage safeguards), dedicated SK API key and secret, and a stable independent random 32-byte rate_key_hex. Never commit credentials or configure the provider from a request. Verification is an explicit authenticated owner CSRF-protected HTTPS form action, never an Agent-initiated SMS or login/2FA feature. Provider charges can apply after explicit enablement and user request. No actual SMS was sent during this build.

The fixed HTTPS adapter uses Basic authentication, certificate and hostname verification, no redirects or proxy, 10-second total HTTP timeout and bounded response size. It accepts only the exact account/service/destination/SMS channel and verification ID, checks the creation time on start, and approves only an exact status=approved receipt from VerificationCheck with the persisted VE SID. No custom codes, direct approval calls, caller-supplied URLs or automatic retries. A lost or ambiguous result, including a 404 after Verify deletes a challenge, never implies success.

Before any provider effect, serialize and persist the reservation. Start limits are one SMS per account or destination per 11 minutes, at most three per rolling 24 hours per account/destination, five per minute and 50 per day per installation; even uncertain sends count. No resend within a live ten-minute challenge. Five code checks maximum. Number change, removal, expired challenge, stale revision, wrong owner, changed provider scope or revoked account cannot verify a replacement. Number possession expires after 90 days. Verification status is a distinct private read model: the earlier preference DTO remains non-executable and its verified=false field is not the canonical possession receipt. Any future call admission must recheck the current verified number and its revision inside its own authoritative transaction. Verified possession is not authorization for automated calling or recording. User call preferences remain separate. Rate evidence is HMAC-pseudonymized, pruned on subsequent starts after 24 hours, and preserves abuse limits across account deletion; the current challenge is deleted with the account. No code or raw phone is stored in the verification ledger or returned in status.

Setup and upgrade install the additive verification tables through VP3OperatorOwnerPhoneV1. Tests use a synthetic response adapter, isolated SQLite and dedicated MySQL CI; no live Verify or Twilio Voice calls. Official contracts: https://www.twilio.com/docs/verify/api/verification and https://www.twilio.com/docs/verify/api/verification-check. Real provider account configuration, live verification acceptance, scheduled cleanup for rate evidence, and owner-call dispatch remain separate gates.
