OPERATOR SPECIALIST — AUTO CALL CONTACT AUTHORIZATION V1

Install via the regular Cloud package and run upgrade.php. Existing contacts stay off; installation never creates a permission, a call intent or a recording job. Manual calling still works before the upgrade.

In the owner’s saved private Agent Chat, choose the assigned line under Phone / Connections. Enable recording with administrator approval, then enable Cloud transcription and retained audio in After calls. In Phone / Contacts, open Agent Auto Call for an individual contact. Review the exact assigned Agent, caller line and current international primary contact number. Save an explicit owner permission with a valid IANA time zone, a same-day calling window, 1–3 calls per day, at least 60 minutes between calls, and a 1–15 minute call duration. Uncheck and save to revoke. Reassignment of a line invalidates prior authorizations; a changed binding requires review. The revision protects against overwriting a newer edit. The owner can revoke an existing authorization while its recording prerequisites are disabled.

This version stores preferences only. It does not create a callable tool, calendar job, autonomous session, provider request or charge. A stored permission is NOT evidence of the recipient's agreement to AI contact, recording or transcription. The next executor release must independently verify called-party consent, applicable communications and recording rules, current destination and line identity, owner scope, revocation, rate/cost budgets, schedules, disclosure, recording/transcription readiness, stop and handoff behavior, and fail closed on uncertainty. No automated call transport is enabled by this migration.

Verification: the existing phone workspace runtime fixture covers SQLite and MySQL, strict validation, scope, CSRF, revisions, recording prerequisites, destination changes, line revocation and no side effects on call/recording ledgers. The upgrade fixture checks read-only readiness and explicit installation. The browser fixture exercises draft persistence, desktop/mobile editor and blocked-prerequisite revocation. Hosted CI and actual device validation remain release gates.
