# Phone Sync PS4 — explicit connected-phone calling from Phone Tracking

The selected connected user’s Communication tab opens the existing Phone drawer without navigating away. The owner selects an existing authorized assigned Twilio line and explicitly confirms one browser call. The map sends only device/profile IDs and revisions, not a phone number. The signed carrier callback rechecks the current approved pairing, both calling permissions, exact linked conversation and number revision, quiet hours, and the assigned line. The preparation ledger enforces the holder’s rolling daily and minimum-gap limits (including canceled/uncertain attempts) and the existing owner busy/rate limits. The call is capped to three minutes; recording and AI captions are disabled. The existing Voice SDK and shared microphone lease are reused; the authenticated map allows microphone access from its own origin only. Browser permission is still required; opening the drawer never captures or dials.

The private raw number is used server-side for the carrier and stored in the existing protected phone call ledger. The connected-call projection masks the destination, and generic contact-saving cannot extract it. A paired call is not identified by caller ID and is not automatically a CRM contact. The selected profile’s Activity tab shows up to five recent call reservations/statuses without exposing numbers, and the existing Chat delivery records the call in its linked conversation. Historical pairings may share an existing conversation; calls are independently attributed to the immutable profile, not inferred from that conversation or number.

This implements a human-controlled browser call path, not autonomous Agent speaking, mobile-app voice calls, inbound identity routing, new number purchase, recordings, or an automatic disconnect of an already-connected call when permissions change. Before carrier admission, stale or revoked permissions fence dialing; current connected calls can be hung up in the Phone drawer and have a short duration cap. Real carrier/browser microphone acceptance is required after release. No actual call or paid request in CI. Existing manual phone workflows remain separate.
