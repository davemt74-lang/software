# Guided Learn my voice in Chat

Owner Chat requests for voice recognition enrollment use a bounded model-selected voice_profile/prepare operation. The authorized action opens a local Chat card, never a microphone or a saved-profile receipt. Typed, streaming and legacy Chat use the same action. Cloning and output voice settings remain separate.

The card lists owned participants, supports explicitly introducing a new participant, explains the roughly 124 MB local model component and asks for local voice-feature consent. Continue prepares/caches the model through the existing trained component with download/check/start progress in Chat. Record sample captures five seconds from the existing voice owner's PCM processor; it never requests a second microphone. The guided capture pauses browser speech recognition and uses local PCM only, so training audio is not sent to the transcription service. Ordinary listening resumes afterward when it was previously enabled. Samples stay staged until the user accepts three previews and selects Save voice profile. Save atomically replaces only that participant's trained voice feature record. Existing acoustic profiles, visual samples and clone settings remain intact. A partial or cancelled enrollment does not replace the previous trained profile.

Each sample has temporary WAV playback, an accept action and a record-again action. Raw recordings and embeddings are never included in Cloud Chat or participant requests. Audio previews exist only in memory and are cleared/revoked on completion, cancellation, a hidden page, conversation change or unload. A bounded local text activity history is scoped by account, Agent and conversation, and is shown when setup is reopened on that browser. It is not a Cloud-synchronized recording archive.

While guided enrollment is active, spoken sample phrases are consumed locally and do not become general Chat turns. The prior listening preference is restored after each capture using the existing enrollment lease. Quiet/clipped/short samples, blocked audio capture, failed downloads and failed saves have visible retry/cancel actions. Stop/cancel and late-operation fences prevent revived capture or saving after the setup ends. The final greeting action enables the existing recognition path; short-phrase accuracy and simultaneous-speaker separation are unchanged. No database migration.

Validation includes production Chat endpoints, planner/final authorization cases, actual guard/adapter/model-component integration in the browser with controlled PCM/model inference, cancellation, persistence/account isolation, mobile layout and existing real WavLM inference coverage. Browser fixtures do not establish real-room recognition accuracy; user enrollment and deployed microphone acceptance are required.
