# Agent action follow-through release plan

Baseline: main `9e696f101735480f773c44156e34e51659f07cf7`.

The main Agent observes the existing situation stream, advances useful permitted work through existing domain tools, verifies the result and returns it to the same Chat. Preparing prose, requesting review, committing a change and proving a public outcome remain separate states.

## Section 1: A proposal becomes a real action

Scope: private task creation/status, named list creation/membership, reminders and personal calendar events. This is the first registered action bridge; paid creation, public publication and outbound communication retain their existing separate domain review paths.

Acceptance criteria (one point each; all must pass for 10/10):

1. Exact saved owner, Agent, conversation, proposal, revision and original reply bind the typed plan. Model text cannot grant authority or select arbitrary executors.
2. The existing Chat displays immutable concrete parameters before a subsequent owner approval. Unrelated pending confirmations remain untouched.
3. All real effects use existing canonical task/list/reminder/calendar kernels and native readback.
4. Fresh permission, source and saved-turn checks plus local effect and canonical workflow receipt commit atomically. No inference holds that transaction.
5. Duplicate requests, competing tabs, lost acknowledgments and process failure cannot duplicate, reopen or overwrite an effect.
6. An action changing its own source has a narrowly proven before/after transition. Unrelated edits, including unsampled list members, remain stale.
7. Revocation, account/Agent switching, a newer conversation turn and cancelled reviews prevent late effects or private delivery.
8. Main Chat HTTP and streaming paths share the same flow; desktop/mobile show exact review and real completion receipts.
9. Actual MySQL concurrency and real browser tests prove the behavior, alongside relevant existing regression suites.
10. Exact reviewed PR checks and applicable post-merge checks pass; the original GitHub production artifact matches the merge tree and is delivered.

## Section 2: Durable follow-ups

Build next from the newly validated main. Use the existing reminder ledger and worker; no parallel scheduler. Bind scheduled/conditional revisits to the exact original proposal, Agent and source. Ambiguous time means clarification. Revisit wakes a fresh assessment and never reuses the prior action approval. Prove atomic schedule/provenance, timezone/DST, cancellation/reschedule races, duplicate wake suppression, source revocation, correct Agent presentation and execution with the browser closed. Conditional Mission/call completion must come from canonical terminal evidence.

## Product, content and promotion

Continue the owner-approved product objective through existing Commerce, media/image, campaign, Profile and compatible destination executors. Complete private photo drafts into valid commercial records; create private marketing artifacts; review exact terms/content/audience/destination/cost; publish only through current domain authority; verify the actual public projection or delivery receipt. Profile Agent reads the existing explicitly public offer, rather than copying private drafts into Knowledge. A connected destination without a declared write capability remains unavailable. Generated, published, sent and converted are separate verified outcomes.
