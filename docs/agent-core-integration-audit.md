# Agent core integration audit

Baseline: `main` at `f55405538ad57a3caf23201c303dbe0eb0cc9778`.

This is a source-level integration audit of that baseline. It records what is implemented, which ordinary Agent paths actually invoke it, and what the background Initiative planner can reach. It is not proof of production configuration, a running worker, an enabled account permission, a configured provider, or a successful live deployment. File and line references refer to the baseline commit, so later changes can move them. Findings below are baseline findings; the release implementing connected defaults can mark individual findings resolved without rewriting the historical evidence.

## Changes in this release

The patch following this audit connects ordinary focused saved owner Chat to the existing Initiative loop automatically. It distinguishes a missing preference from an explicit Pause, resolves the Agent from the owned conversation, and corroborates the exact accepted activity observation before creating or moving the binding. GET status reads remain read-only. Source permissions and configured inference routing remain separate from core activation.

This is a connected core section, not a claim that all 63 foreground catalog entries are now available to background planning. The remaining commerce/promotion, conversational existing-image editing, Connected Sites discovery, media/sensing and natural visitor-announcement gaps below remain open. The new check-in is a real saved text turn; it does not force a greeting, add a new widget, or automatically speak.

An initial unsaved Chat still needs its normal canonical conversation record before work can be scheduled; this happens when the first message is saved. A real hosting scheduler/Cloud worker is still required for operation with every browser closed. Installing files and schemas does not provision HostGator cron or establish provider/account runtime readiness.

## Main finding at the baseline

The application has substantial working tool infrastructure. The disconnect is between foreground tools, background preparation, context selection, and presentation. The foreground capability inventory contains **63 entries**, while the background Initiative catalog offers at most **seven choices**. A capability entry is readiness evidence, not proof that every feature is enabled or that a model request has executed it.

The seven background choices are `work.prepare_private`, `brain.read`, `knowledge.search`, `missions.prepare`, `workbench.product.review`, `workbench.screen.review`, and `workbench.mission.review`. The three Workbench choices appear only when eligible exact sources exist. `missions.prepare` saves an approval-pending Mission; it does not launch approved research. The Workbench choices present existing confirmation flows; they do not themselves generate a product, edit an image, or complete a decision brief.

Evidence: `includes/agent-capability-awareness-v1.php:91`–`154`; `includes/agent-initiative-tools-v1.php:121`–`160`.

## Greeting and attention presentation at the baseline

The baseline has three distinct mechanisms that should not be described as one completed natural greeting system:

1. **Greeting preview.** The query-controlled preview only decides `would_mention` for a specific open linked meeting-prep follow-up starting within 30 minutes, after the idle threshold. It returns a decision/reason, not a generated greeting or delivery. Evidence: `chat.php:518`; `includes/cognitive-presentation-v510.php:421`–`437`.
2. **Live Top-of-mind projection.** It projects the top working item into title/summary/link fields and renders a templated “Agent check-in” or “Top of mind” message-like element. This is source-backed UI, not a saved natural Agent turn. Evidence: `includes/cognitive-presentation-v510.php:406`–`417`, `:441`–`457`; `chat-cognitive-presentation-v510.js:310`–`335`.
3. **Initiative's real result delivery.** A model may select useful jobs and generate a substantive private result. Canonical verified delivery then saves that result into the bound Chat. This is actual generated work, but only after activation, eligible evidence, routing and worker/pump readiness. Evidence: `includes/agent-initiative-v1.php:808`–`865`, `:617`–`644`.

The initial catch-up candidate selection is still deterministic: source readers assign priorities, sorting orders them, and the returned brief slices a small presentation budget. That can be useful as an input filter, but should not be mistaken for model reasoning over the complete account. Evidence: `includes/agent-catch-up-v1.php:267`–`289`.

## Verification scope and release follow-through

This audit inspected source paths, invocation chains, source filters, persistent writes and readiness/confirmation checks at the stated baseline. It did not execute live external services or prove an account/deployment's configuration. The building release should attach concrete tests and current resolution status to each changed gap, including normal typed/voice Chat, missing versus paused policy, undated tasks, standalone situations, multiple owner tabs, account switching, stale responses, owner-away delivery, and source revocation. Provider-dependent image/call/payment behavior needs its own configured-runtime proof before being described as live.
