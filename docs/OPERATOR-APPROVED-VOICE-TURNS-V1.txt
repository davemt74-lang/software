OPERATOR SPECIALIST — OWNER-APPROVED VOICE TURNS V1

Before enabling browser calls in an authorized private Chat, optionally choose Prepare Agent voice for browser calls. This prepares a local Twilio SDK AudioProcessor and Web Audio graph; the original human microphone is the default outgoing audio source. Preparation does not open another microphone, synthesize speech, dial or authorize AI participation. The processor is registered before the browser Device connects, and it must match the actual outgoing track before an Agent voice turn is offered. Standard unprepared calls remain on the existing unmodified path.

During an answered call, explicitly enable live captions and private suggestions with everyone's consent. Review a short current suggestion (up to 180 characters). Ask everyone for agreement to hear the AI assistant and confirm the exact script, which includes a fixed AI identity disclosure. Prepare approved voice sends only that script to the configured Cloud speech service for a stock synthetic voice. A separate Speak approved response click obtains a single-use playback claim. The same suggestion cannot reserve another synthesis or play twice. This is an owner-approved relay, not autonomous Agent speech. No new call, carrier invitation, impersonation or automatic reply is initiated.

Speak approved response temporarily gives the Agent the outbound microphone channel. Add Agent to call instead mixes the approved audio with the live owner microphone and plays the same Agent audio for the owner. After that response, the call card keeps an explicit Agent-in-call state. Another reviewed suggestion can become another approved Agent response without adding the Agent again. Every response still requires its own exact-script review, consent confirmation, synthesis request and playback click.

Remove Agent from call stops active Agent audio immediately, closes its current voice turn and preserves both human audio paths and live captions. Removing an idle Agent clears only its call-level presence. The local speaker receives only the Agent audio from this mixer. Take over now, Escape, stop captions, mute, changed Chat, permission loss, foreground loss and call/device teardown interrupt the synthetic source and restore human control. Takeover closes the live assistance session; the same call cannot restart AI assistance. If the prepared browser audio path itself fails, reconnect the phone; do not assume the remote party is hearing a silent or interrupted microphone. The client checks server authority while playing, but network delay and carrier/media delivery are not equivalent to an instantaneous server-side audio cutoff. Local removal does not wait for a server response.

Limits: one synthesis per verified suggestion, at most two reserved turns per call and eight per rolling hour; at most 20 seconds of PCM audio per turn; a short preparation/claim window within the existing caption permission lifetime. Caption and model dispatch pause during the reserved turn. A failed or uncertain paid request is not automatically repeated. The voice-turn table stores only authorization metadata, hashed tokens, counters and duration; scripts and generated PCM are transient in the browser/server request. Existing carrier recording, disclosure and after-call processing are unchanged; a voice turn is not a proof of recipient consent or complete carrier delivery.

Install the optional voice-turn metadata table using the usual Cloud database upgrade. No autonomous dialing, free-form speech tool, voice clone, or automatic model-to-audio loop is added. Future automatic turn-taking and caller interruption require verified full-duplex media transport, explicit recipient consent, cost limits, and device testing.

Verification includes exact-call/Agent/Chat scope, authenticated suggestion proof, independent consent, paid reservation/replay, separate playback claim, stop during synthesis, mixer natural completion and immediate interruption, persistent Agent presence after natural completion, explicit removal without ending either human track, and a browser journey with synthetic remote and local tracks. These tests do not use real carrier or paid provider requests. Full hosted CI and actual Twilio/browser/Cloud speech verification remain release gates.
