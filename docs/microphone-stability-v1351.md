# Microphone stability and hidden-page camera preference v1.351

Ordinary Chat recognition now stays continuous through final speech segments until the existing turn-end pause commits the message. Repeated Listen requests preserve the active recognizer. A pending monitor acquisition can be cancelled before native recognition starts, and both ordinary listening and barge-in wait for that same acquisition. Speech completion clears cancelled startup flags before resuming.

Unexpected recognition failures use paced retries; native onend cannot overwrite the pending retry delay. A native session that never releases is bounded and reports a reload action rather than leaving an indefinite connecting state or opening overlapping sessions. Barge-in now has startup timeout, permission/device failure handling and bounded failure retries. Stop and temporary-response expiry still fence late work and release owned media. This is browser speech recognition, not an offline speech engine; live device and service behavior still needs the deployment test.

Agent Eyes has an account-and-browser-owned “Pause camera when this page is hidden” checkbox. It defaults on. Off preserves an already-started camera and continues available scan timers when hidden. The adapter bypasses only the visibility restriction for that explicit setting; secure-context, other camera owners, HomeServer privacy state and explicit Stop/page unload remain effective. TV screen-sharing and microphone reply windows keep their own controls. Browsers may throttle background inference.

Regression tests reproduce the prior stuck connecting state during slow microphone acquisition and cover repeated starts, multi-part names, unexpected abort pacing, a missing native release, permission failure during barge-in, camera visibility preference persistence and background camera scans. Speech service and model outputs are controlled fixtures. HomeServer camera source is staged locally only; no HomeServer publication or repository workflow is part of this release.
