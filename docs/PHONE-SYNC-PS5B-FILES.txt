# Phone Sync PS5B — protected file and photo exchange

Extends the existing Information tab and holder inbox with Request a photo, Request a file or document, and Send a file. Owner shares only an explicitly selected attachment. Holder accepts a request, selects a local file, and explicitly approves sharing before upload. No background phone storage browsing, remote camera activation, SMS, Web Push, external file URLs, or automatic Agent processing. A private Chat status receipt points to the same Phone Tracking profile.

Initial format policy: JPEG/PNG images, PDF and UTF-8 plain text, maximum 2 MiB per file. The server checks decoded byte size, content-based MIME detection, basic image size/signature and document framing; it does not provide malware scanning or prove files are harmless. Original names are not stored; generated filenames are used. Original photo metadata is not stripped. Downloads are explicit, integrity checked and delivered as attachment-style octet streams via the authenticated foreground panel, never embedded or executed. Files are held in a separate database BLOB table, not webroot; database storage is not independently encrypted by this build. Existing HTTPS, owner session/CSRF, paired-device cookie and origin checks apply.

Transfers bind the current owner, approved pairing, profile revision and exact request version. Both users must allow information exchange. No text-only completion for photo/file requests; each exchange has at most one immutable attachment. Lost acknowledgements may retry only exact content digest and operation. Per-device and per-account storage limits: 6 MiB and 20 MiB respectively. Existing request rate caps apply. Pending request lifetime 24 hours; attachment access expires after at most seven days, and expired bytes are removed opportunistically during later uploads. Any communication revision change deletes associated attachment bytes conservatively; cancel/decline deletes the file, and disconnect cascades. Already downloaded copies cannot be revoked. Scheduled retention cleanup, scanning, larger media, in-app previews, and owner-approved Agent analysis remain separate work. No real user files or paid provider calls in CI.
