OPERATOR SPECIALIST — AUTONOMOUS CALL READINESS V1

This release is a private, read-only preflight and explicit recipient agreement review, not an autonomous dialer. The execution function is unconditionally false. No executable call job, carrier request, spend reservation, recipient invitation, automatic recording or model request is created by the readiness feature.

In a saved private Chat, choose the assigned Agent line and open Phone / Contacts / Agent Auto Call. Save the contact policy, then open Auto Call readiness. Review the exact caller line, current saved primary destination, and a limited agreed purpose: follow-up, appointment confirmation, or recipient-requested check-in. Record affirmative recipient agreement to an AI-initiated call for that purpose, AI disclosure, recording and transcription only if it actually occurred. An owner attestation is not independent recipient authentication, evidence of legally sufficient consent, or authority to dial. Its seven-day review expiry and exact binding include the owner, contact identity, current destination, assigned line, owner policy revision, and recording policy revision. A changed binding requires review. Clearing a review does not record a recipient opt-out; record withdrawal separately when requested by the recipient.

A recipient withdrawal suppresses the destination across all of that owner's Agents and duplicate contact aliases. The withdrawal cannot be removed by ordinary owner attestation or by resaving Auto Call permissions. There is intentionally no opt-out removal UI in this release. The destination hash is scoped metadata, not an anonymization or recipient identity proof. The existing manual phone controls are unchanged.

The readiness snapshot checks current owner policy, local time window for the entire maximum call duration, known outbound browser ledger attempts across that owner's Agents/destination, minimum interval, existing unsettled phone sessions, and native Cloud Calendar conflicts. Calendar coverage is limited to the available Cloud projection; other calendars and the recipient's availability are not verified. Known browser attempts are not a complete future autonomous quota ledger. Unknown or changed inputs block local checks rather than silently passing. Refresh explicitly for current results; a previously displayed snapshot is not a lease. Even if all local checks pass, independent recipient verification remains unverified and spend/dispatch remains disabled.

Install the metadata tables through the standard Cloud upgrade. GET reads never install or modify consent; POST writes require the existing authenticated owner, exact Agent/Chat/line/contact policy and consent revisions, and CSRF. Consent withdrawal commits before optional preflight projection. No speech, consent evidence document, private report content or provider secret is stored in the new tables. The existing contact, voice and recording ledgers remain authoritative.

The next executor must have a separately reviewed recipient-consent mechanism, durable opt-out enforcement and budget reservation at dispatch, exact call objective, real carrier/recording/stream verification, interruption and reconciliation, global kill switch, and physical device/provider tests. Do not interpret existing Calendar reminders, preflight results, owner attestations, model suggestions or phone numbers as runnable call instructions.

Tests extend SQLite/MySQL Phone workspace, explicit database upgrade, and browser fixtures to exercise default-off readiness, CSRF, stale policies/revisions, exact destination, restricted purpose, expiry, recording policy change, local time and known attempt limits, destination suppression across aliases and zero call/recording/Chat/Calendar side effects. Full hosted CI remains required.
