# Agent Eyes sharing sessions in My Knowledge

A successful Share screen action creates a named session folder through the canonical `shared_folders_v161_create` service. The folder is the same owner-owned `artist_transcript_folders_v177` row shown by `knowledge.php`, Transcriptions and Music. Opening Eyes or cancelling the browser picker creates no folder. Start retries reuse their session ID. Source data stays private; creating a session does not publish Knowledge or change sharing policies.

Capture saves an image and optional user intent note. Capture and analyze and automatic analysis save a timestamped capture before running the existing Cloud vision route. The account-owned capture store retains bounded JPEGs (1280 px maximum); images never enter a public uploads path, Knowledge search chunks or Brain. Each capture gets a private canonical Personal Knowledge note and source reference, indexed through the existing Knowledge and cognitive-event path. Structured observations include visible music progress, products, articles, errors and project details with confidence labels. Displayed playback progress does not establish actual listening or completion. Captures are limited to 1000 per account; deletion is explicit, with no automatic destructive retention rule.

The Eyes history panel lists sharing sessions, opens the actual My Knowledge folder, shows/analyzes old captures, saves to Brain, and adds source-labelled text to the current Chat draft. Research in Chat prepares a research request for the existing Chat Research workflow; it does not silently launch a research job. My Knowledge folder views include the same session history and screenshot/detail actions. A session can be ended while its history remains readable and reanalyzable. Folder rename/move controls remain the canonical existing UI. If its folder is deleted, new captures stop rather than creating a replacement or silently re-filing them.

Transcribe tab audio is off by default. Checking it before Share screen requests audio in the native display picker. The selected surface must be a browser tab and provide a live audio track. No microphone, browser SpeechRecognition or voice-permission flow is started or changed. Missing audio is reported with instructions to select a Chrome tab and Share tab audio. Disabling transcription cancels its pending uploads and clears current Chat audio evidence without stopping screen sharing.

Tab audio is measured locally and encoded as independent 15-second MediaRecorder segments, with a bounded upload queue, visible backlog/errors and silence skipping. Stop finalizes the last usable segment, finishes accepted uploads, then ends its session. Deletion cancels uploads and stops the surface immediately. The speech endpoint uses existing server-side ElevenLabs credentials, Scribe v2, AI entitlement and a separately locked account rate/concurrency budget. It accepts bounded audio containers up to 1 MB and retains only transcript text, not audio files. PHP temporary uploads expire with the request. A usable speech-service credential is required; a live credentialed provider test remains a deployment acceptance check. UI transcripts are chunked, not word-by-word live captions. Current screen/transcript evidence is bounded, short-lived, account-bound and never instruction authority.

Send to Brain is off by default. When selected, successful new analyses/transcripts are promoted using the existing Agent Brain service and the sharing session's server-resolved conversation Agent namespace. Users can also promote individual historical captures. Repeat promotion updates the same capture memory. Knowledge notes exist independently of Brain promotion. This provides source evidence to the existing recall/cognitive systems; it does not introduce an autonomous pattern detector, recurring schedule, new Mission executor or automatic shared publication in this phase.

Delete session data removes session captures, pixels, transcripts, generated Knowledge notes and their search chunks. A separate checkbox determines whether its exact capture-specific Brain memories are removed. The folder and unrelated/moved-in Knowledge items are preserved. A small content-free tombstone prevents late capture/analysis results or retried session IDs from resurrecting deleted data. Research reports, Missions, Chat messages and deliberately retained Brain memories are separate user records and are not silently removed. Future cross-module derived records must retain explicit source references for invalidation.

Acceptance: share a Chrome tab, observe its Knowledge folder, save/analyze a screenshot showing a music progress value, enter an intent note, stop sharing and revisit the same folder. Save a capture to Brain; repeat without duplicate memories. Enable tab audio before sharing, check the meter and saved transcript, then switch it off. Delete a selected session with and without Brain removal. Verify another account cannot enumerate sessions or obtain pixels. Test model failure, unavailable speech credentials, picker cancellation, session deletion during provider execution and mobile layout. Automated browser fixtures use real canvas/display and MediaRecorder audio streams with mocked model/speech responses; live native picker/ElevenLabs behavior needs user deployment testing.
