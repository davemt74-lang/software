CONNECTED PHONE — AGENT WORKSPACE V1

What this release adds

Every approved connected phone shows an AGENT tab for private Agent results,
important incoming Gmail, email drafts awaiting review, generated images and
saved private canvases. Before private access is approved it shows an approval
screen. Home, Chat, Requests, Phone and Help remain available.

Phone setup: no phone user login

1. Pair and approve the phone through the existing Connected Phone flow.
2. In the signed-in main app, open Phone Tracking, select that phone, then
   Permissions. Enable "Allow AGENT on this phone without signing in", select
   its Agent, and save. A role label or ordinary pairing alone is insufficient.
3. On the phone, open AGENT and Check for approval. This uses its existing
   paired-device cookie and an anonymous CSRF session; no owner login or
   password fingerprint is written to the phone session.
4. Enable Agent notifications if wanted, and complete the separate phone push
   subscription/permission setup. Notifications contain a generic invitation
   to open VP3 Phone, never an email subject, recipient or body.

Only the main app can grant or change the phone's selected Agent. The phone can
turn its Agent alerts off or remove access. Revocation, device expiry, credential
rotation, password changes and current account/Agent/Chat permission changes
invalidate the private scope, including an already-open review. The approval
never authenticates the main app or unlocks its direct private API routes.
Older session-based enrollments remain compatible while signed in; they are not
silently migrated to no-login grants. The main owner must explicitly approve.

Send a Canvas

The Canvas build/editor has "Send Canvas to Connected Phone". Choose an approved
phone and confirm its private Agent access. This can approve the phone for the
Canvas's Agent without signing in there. The exact saved Canvas is delivered as
a canonical private reference; no copy or public publication is created. A
recent unread delivery appears first in AGENT even if the Canvas was created
before other results. Retry receipts prevent duplicate deliveries. Changed
Canvas/device/approval versions require a fresh selection. Alerts respect the
phone's separate notification choices; availability does not prove display.

Using the tab

All, Needs you, For you and History filter the same source-backed work items.
The feed spans currently authorized private Chats of the selected Agent, with
bounded saved-source coverage. Completed results require a native completion
receipt; this feed does not label every Chat answer as a completed result or
copy the entire Gmail mailbox.
Mark read, Acknowledge and Snooze record separate phone receipts; none sends an
email, changes a Gmail read label, resolves a Gmail matter or proves delivery.
The tab never runs model inference, scans Gmail or makes calls merely to load
its feed.

Email drafts open the existing Gmail composer on the exact saved draft. The
owner can edit a new-mail draft's recipient, subject and body, attach an owned
saved/uploaded image, generate an image with the normal native review, save the
draft or send the exact reviewed version. Canonical replies and follow-ups keep
their source-bound recipient and subject. Existing stale-draft, token expiry,
source-change, send reconciliation and response deadline checks remain authoritative. Leaving
unsaved edits offers Save draft and leave, Keep editing or Discard edits.

Important-email cards come from the current saved Gmail classification and
mailbox grant. They identify the mailbox as their origin. Their selected-Agent
Chat is a discussion destination, not a claim that the email originated in that
Chat. The native reader preserves formatted email styling with the existing
sanitization and explicit remote-image choice.

Images use the original private generation and owned asset. Canvases use their
original private version, runtime sandbox and app-data permissions. Opening a
phone Canvas does not publish it. Active apps save state with native revision
checks; saved previews do not overwrite the active app's data. Generated code
cannot access the parent owner session or unrestricted network.

Results, drafts, images and canvases keep their original Agent/Chat provenance.
Open original Chat is an optional link into the main app and uses its normal
account access; native phone review does not require opening that link. The mailbox-wide
important-email action instead says Discuss with your Agent. A conversation
is created only when the main owner explicitly approves/selects an Agent and
none exists; background reads never create conversations.

Deployment

Extract the complete production ZIP into the existing installation, preserving
the installation's config.php, private/ and uploads/ directories. The archive
excludes these local files, secrets, tests and development tooling. Run the
normal authenticated upgrade.php flow before using the new tab. setup.php and
upgrade.php install the workspace index, explicit owner enrollment, per-device
receipts and bounded background sweep metadata through the existing phone
installer. Live requests do not run schema migrations.

Keep the normal Cloud Agent worker and existing Web Push delivery worker
scheduled. The Cloud Agent worker indexes a bounded number of current opted-in
owner enrollments and queues eligible opaque notification events. The existing
Web Push worker remains responsible for delivery. Old visible work is
backfilled silently when notifications are enabled. Push display/open receipts
are separate from item reading, acknowledgment and email approval.
Read and acknowledged items suppress queued delivery; snooze suppresses it until
the deadline. A native source edit has a new semantic revision. Saved source
timestamps, rather than indexing or polling time, determine the notification
cutover, and historical important-email records remain quiet.

The device cookie retains its existing exact API path. Private viewer and
native action routes are dispatched through that path and require the exact
paired credential plus a current explicit main-owner device grant. The
anonymous session supplies CSRF and review nonces, never a main-app login.

Scope of phone calls

The subsequent Gmail owner-call integration is documented in
GMAIL-OWNER-PHONE-CALLS-V1.txt. It adds a separately enabled email-call channel
through the existing Operator engine, linked to this same private item.
Optional voice confirmation requires the exact email to remain open in the
authorized exact phone review. Answering a call or a generic "yes" is not an email
send approval, and an app-closed carrier callback cannot send Gmail.

Acceptance gates

1. Explicit main-owner approval; pairing and role labels alone cannot enter.
2. Exact account/device/credential/Agent/Chat checks on every private request.
3. Source-backed feed with deterministic IDs and bounded, scoped pagination.
4. Distinct read/acknowledge/snooze receipts with stale-version rejection.
5. Exact native Gmail review/save/send and unsaved-edit protection.
6. Formatted important email with current mailbox classification and grant.
7. Native images and isolated private canvases, with canonical app state.
8. Opted-in background pushes, opaque payloads and exact-item routing.
9. Home/Chat/Requests/Phone, visible AGENT gate and one visible scroll area.
10. Native database, browser, package and exact-commit deployment verification.

Tests use isolated database/browser fixtures and deterministic provider
substitutes. Release verification does not send real emails, call phones,
deliver push messages to real devices or incur provider generation charges.
