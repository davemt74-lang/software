# Navigation, Music sidebar and typed/voice routing recovery

The reported “Load from the asteroid you saved me” request and follow-up “Yes” had no model-selected navigation adapter. Existing Studio navigation was available only through a literal open/stem wording path. Add a bounded navigation plan to shared capability discovery, so typed, streaming voice and legacy Chat can resolve an authorized saved track or a canonical member page. A direct load/open request returns the navigation action. A current Studio offer (including a single saved media offer in an existing conversation) can be resolved by an affirmative follow-up. No arbitrary URL or script is accepted.

Current owner, Agent conversation, track management and canonical member visibility are rechecked. Ambiguous catalog matches ask for a choice. Stale/foreign offers do not execute. Final automatic navigation requires the executor's per-request approval reference; a model's action tag does not confer authority. Navigation receipts request a browser action and do not claim that the destination loaded. Studio links retain the active conversation, listening flag and return route. Stem bootstrap derives the named Agent ID from the owned saved conversation.

The legacy Artist account type remains in permissions compatibility code. The current Music Workspace model uses enabled plugin state and contextual workspace membership, rather than that global role. The main sidebar now promotes the existing authorized Music Workspace entry into a Music section with workspace, library, releases and player destinations; it does not assign roles, enable plugins or grant track permissions.

The mature Stem Studio agent remains loaded by admin/stems.php through admin/stem-agent-v131.js and api/stem-agent-v105.php. Its registered surfaces include playback, mute/solo/level/pan, tempo/metronome, effects, routing, automation, clip edits, projects/versions and undo/redo. The actual v127/v128 verified execution suites and v131 integration suite pass. These editor commands execute in the active editor using the existing verified bridge, not by sending arbitrary JavaScript from general Chat. Physical audio, provider interpretation and deployed browser acceptance remain user checks.

Automatic compute could select Cloud for an unready HomeServer yet retain try_homeserver=true, causing typed Chat to dispatch a turn and then report an unconfirmed result. v4.20 now honors that selected Cloud route and skips the HomeServer Chat recovery probe. Ready Automatic HomeServer and explicit HomeServer-only recovery remain supported. Streaming also uses the existing unconfirmed-dispatch fence before any fallback, matching typed behavior and preventing accidental replay of a potentially mutating turn. Explicit Cloud continues to avoid HomeServer discovery entirely.

Validation includes the reported Studio sequence across real typed/voice-stream/legacy endpoints with controlled models, current-catalog and action-authorization tests, seven actual planner cases, existing Studio verified execution suites and combined-main Recovery Baseline. Browser CI checks the Studio link handoff. This build includes merged PH3G–PH3I-B phone updates from main. No new navigation schema is added; run the normal deployment upgrade for any earlier list/phone additions not yet installed.
