# CD1 engineering contract (proposed)
## Scope and sequence
A protocol; B identity; C additive schema; D pairing/credentials; E capability manifest; F policy; G legacy adapters; H twin; I simulator; J canonical announcements; K dashboard; L verification. Recheck current heads and active PRs. HTTPS first, no MQTT dependency.
## Wire envelope
Protocol vp3.device.v1. Strict JSON object, reject unknown fields, duplicate keys, malformed UTF-8 and unregistered message types. Required fields: protocol (constant), message_id, device_id, installation_id, session_id (opaque strings 16–80 chars), message_type (registered dotted name <=80 chars), sequence (integer 0..9007199254740991), timestamp (RFC3339 UTC), policy_revision (positive integer), payload (strict type-specific object). Optional correlation_id null or bounded opaque string. Session-open and pairing use separate pre-session schemas; do not require a session ID before issuance. Authenticated binding is authoritative, not body IDs. Define exact schemas and cross-language fixtures in CD1A.
Initial types: device.session.open/close, device.heartbeat, device.state.report, capability.manifest.report, device.input.received, announcement.deliver/acknowledge, command.deliver/acknowledge/result, policy.updated, session.revoked. Direction and permission allowlists required. Media/firmware separate transfers.
Proposed defaults: 16KiB control, 32KiB manifest exception, 30s heartbeat, 90s stale, 5min pairing, 60s command TTL, max 3 safe attempts, 24h dedup retention, 120s clock skew. Validate limits; sleeping devices need distinct presence policy. Persist session sequence/replay fences beyond dedup retention; exact retry returns same receipt, changed payload rejected. Server clock governs expiry.
## Identity and storage
Opaque stable device ID; separate installation, credential generation, authority, owner, assigned user, Agent, class, manufacturer/model/revision, firmware/SDK/protocol versions, lifecycle, policy revision. Factory reset erases local credentials but cannot guarantee server revocation offline; owner-approved recovery fences old installation. Transfer clears prior private cache and assignments.
Proposed logical tables (prefix vp3_, suffix _v1): connected_devices, device_installations, device_identity_links, device_credentials, device_pairings, device_assignments, device_capabilities, device_permissions, device_sessions, device_twins, device_events, device_commands, device_receipts. Define foreign keys, owner-scoped uniqueness, credential hashes, generation fences, event/receipt uniqueness, indexes and retention. Do not provision future tables prematurely. Cloud upgrade.php and Otro numbered migrations; no DDL on ordinary reads/heartbeats. Test populated upgrades and rollback/recovery.
## Pairing
Device generates high-entropy verifier; start expiring session; QR/code contains no verifier; authenticated owner reviews device and permissions; device proves verifier; atomically consume code and issue per-installation opaque bearer over TLS. Store hash server-side; protect local storage; rotate/revoke and invalidate sessions atomically. Rate limit guesses, never log secrets, no cross-account lookup leakage.
## Capabilities and permissions
Manifest version, class, array of registered capability keys/version/supported/typed constraints; e.g. display.text max_text_length 512, touch.actions max_actions 4, audio.capture 16000Hz mono, audio.playback, battery.report. Distinguish supported, available, authorized, enabled, active. Device claims never grant authority. Initial permission namespace: device.connect/state.report/state.read/capabilities.read, agent.conversation.start/respond, announcement.receive/acknowledge, display.render, audio.capture.request/playback, haptic.notify, context.location.share/camera.capture/microphone.background, task.assignment.receive, mission.participation, device.configuration.update/firmware.update/physical_action.request. Future operations remain non-executable.
## APIs
Logical routes under /api/devices/v1 (adapt PHP conventions): GET inventory/detail; POST pairings/start, approve, exchange; POST session/open; POST events; GET commands; POST receipts; PATCH device permissions; POST suspend/revoke/rotate. Separate owner session+CSRF from device bearer. No side effects on GET except bounded operational logging if necessary. Errors: INVALID_MESSAGE, UNSUPPORTED_PROTOCOL, AUTHENTICATION_REQUIRED, DEVICE_REVOKED, DEVICE_SUSPENDED, SESSION_EXPIRED, POLICY_CHANGED, PERMISSION_DENIED, CAPABILITY_UNAVAILABLE, COMMAND_EXPIRED, REPLAY_REJECTED, RESOURCE_LIMIT, OUTCOME_UNKNOWN; stable code, safe message, retryable, correlation ID.
## Adapters and twin
Phone, HomeServer, extension, room and fleet adapters map native identities without replacing credentials or widening access. Read-only projection first; native execution stays native. Twin separates desired/reported/verified state, revisions, timestamp, connection and sync status. Stale/unknown/conflict visible. Never claim physical success from desired state.
## First vertical slice
Actual simulator uses backend protocol and credentials, not UI-only mock. Register, connect, manifest, battery, real canonical announcement, acknowledge once, show receipt in Chat, revoke, reject old token. Dashboard inventory, pairing, permissions, diagnostics, suspend/revoke; responsive no nested scrollbars. Acknowledgment is not action approval. No voice, firmware, MQTT or dynamic apps required for CD1.
