# Security and authority
Fail closed. Evaluate authenticated account, assigned user, device/installation/credential/session generation, current policy revision, workspace and app scopes, capability, autonomy, resource budget, mandatory approvals. Recheck at execution and receipt acceptance. Device manifest is untrusted. Deny unknown operations; owner UI and device API separate. TLS, protected credentials, no secrets in logs, bounded payload/rate/retention, replay fencing and account isolation. Future MQTT ACL per device/topic; no wildcard cross-account subscriptions.
Commands: created → authorized → dispatched → acknowledged → executing → receipt → verified; rejected/failed/cancelled/expired/outcome unknown alternatives. Unique execution identity, expiry, exact approval binding, evidence requirements. Never blindly retry ambiguous physical action. Cloud/local authority lease and fencing prevent dual execution; offline grants bounded and expire, no claim of instantaneous remote revocation offline. Physical devices.command remains approval-only in existing HomeServer policy. Sensor access off by default, visible capture indicators, independent consent, local-only no fallback, guest/shared devices no private history. Ownership transfer requires explicit release, credential invalidation and private cache cleanup. Firmware signing, rollback, secure boot/storage where supported; isolated build runners. Threat tests: cross-account IDs, stale policy, stolen token, duplicate messages, expired commands, revoked reconnect, malformed input, conflicting authority, unauthorized sensor access, app permission escalation.
