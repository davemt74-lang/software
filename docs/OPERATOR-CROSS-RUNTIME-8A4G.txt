# Operator 8A.4G — cross-runtime registration acceptance

The consolidated Section 14 authority CI now checks out the exact public HomeServer #380 implementation (0b059239c489655f1c65dbe857c58a73bdf0b3c3) in a separate sparse directory without persisted Git credentials. Python imports the actual credential client, registration transport and supervisor; the fixture dispatches the actual PHP Cloud credential and registration handlers into an in-memory SQLite ledger. No production config or database is loaded. Each test creates an ephemeral certificate for a synthetic host and maps it to a loopback-only HTTPS server; the client still verifies host, certificate and TLS version. The certificate is trusted solely by the test connection factory.

Coverage: browser-independent register/heartbeat/stale/retire, cross-owner isolation, lost acknowledgement with byte-identical replay, boot fencing and recovery after abrupt stop, pairing revocation/replacement and credential rotation, redirect denial, wrong bearer, and no execution claims created. This validates interoperability through real loopback TLS but does not certify your deployed Cloud or HomeServer, firewall/DNS/TLS setup, browser-closed physical operation, real Twilio audio, call authorization or paid execution. No production secrets, calls, recording, models or LiveKit changes.

Manual isolated run: set VP3_INTEROP_HOMESERVER to an exact checkout of the pinned HomeServer revision; run python3 -B tests/operator-worker-interop-8a4.py with PHP 8.3/pdo_sqlite and OpenSSL available. Do not use a production database or configure real bearer values.
