# Phone Sync PS5A — private information exchange

Adds an Information tab to the selected Phone Tracking user and an expandable information inbox on the approved connected phone. Both owner and holder must opt in through the existing communication permissions. An owner can explicitly send an update, ask a question, request availability or ask for a task. The recipient may acknowledge updates, accept or decline requests, and send a text response. An accepted task is not automatically performed. No model, automatic outreach, background push notification, sensor capture, file access, telephone call or paid action is invoked.

The ledger binds the current owner, exact pairing and profile revision. Requests expire after 24 hours; the read window is 30 days with opportunistic cleanup on creation. At most four outstanding requests, eight creations per phone and 32 per account per rolling day. Text is UTF-8, 1000 bytes maximum, rendered as text. Explicit owner and holder actions run under existing account locks and use exact versions. Lost creation replies can retry only the same ID and text; transition retries are exact and idempotent. Changes to communication preferences cancel outstanding work. Removing information consent scrubs old text; disconnect deletes the profile and its dependent ledger. No raw information content is inserted into Chat or model history. Existing scoped phone Chat polls emit content-free receipt notifications linking back to this selected phone, at most once for the current latest state. Intermediate acceptance can be superseded by a later response before the next poll.

Phone Tracking list/holder status only carry open-count metadata. Full text is retrieved for the selected foreground panel, with no browser storage. The panel clears on context changes, offline state and visibility loss. Explicitly refresh or allow foreground polling; no Web Push or SMS. The scope is text-only; protected photo/document upload and download, background push, relationship Brain analysis, and autonomous decisions are subsequent gates. CI runs synthetic fixtures without real user data.
