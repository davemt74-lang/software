# Participant tasks, reminders and presence

Run `upgrade.php` after installing this build. It adds four owner-scoped tables for settings, explicit sharing, recent observations, and heartbeat ordering. Runtime requests never create these tables. Existing tasks, reminders, list membership, phone updates, photo samples and voice samples stay in their canonical stores.

In Agent Eyes → Conversation participant → Participant tasks and presence:

1. Enable participant-aware voice tasks and choose **My recognized profile**. This explicitly associates the selected local face/voice profile with the signed-in owner's task tools; matching names or another account's linked-user field never grant access.
2. Choose another participant and explicitly share current Agent lists, individual tasks or reminders as **Can view** or **Can view and update**, then save. List sharing includes its canonical task items. The bounded catalog shows up to 100 lists, 100 recent tasks and 100 reminders. Update previews include up to 25 items per list and 200 list items total, with explicit partial-preview labels; list notes retain their 200-item canonical read.
3. Optionally enable an update offer once per visit. The offer is generic, without task or reminder titles. Show updates explicitly to read details or open a shared sticky note.

The owner keeps existing list creation, confirmation and reminder setup. Guests can read shared records, add items to an editable existing list, change shared task status, and complete/dismiss/snooze an editable reminder occurrence. Guests cannot create new owner lists, standalone tasks, reminder schedules, permissions or account links. Guest turns use a bounded Cloud-only interpreter with no owner history, Knowledge, calendar or Brain retrieval, including the streaming endpoint. A HomeServer-only compute policy remains local; these participant tools explain that their Cloud interpreter is unavailable instead of sending data elsewhere. Ordinary typed Chat belongs to the signed-in account unless a participant is deliberately selected using **Use in typed Chat**. Unassigned voice in participant-aware mode asks who is speaking.

Recognition remains provisional and does not sign in another user. Each participant accesses their own private account records by signing in to that account. Sharing edits require owner/Agent/resource checks again under the canonical write transaction. Grant changes invalidate in-flight participant plans. Shared sticky notes recheck permissions on every read and have read-only controls; edits go through Chat.

Last seen and last heard are separate server timestamps. Camera heartbeats are limited to four participants and ordered per tab; duplicate inbox voice events do not extend presence. Voice alone records recent speech, not continuous proof of presence or speaker separation. Ten minutes without an observation starts a new visit. A cross-tab lease plus display receipt suppresses repeated offers within the visit. Stop, correction, hidden pages and participant changes fence pending UI responses. Owner reminder automatic presentation pauses while participant-aware mode is enabled; scheduled reminders and delivery records remain stored and are not acknowledged by this overview. Existing manual reminder views still work.

Physical testing remains necessary: enroll voices, say “Hello Longfellow,” test the current speaker with the camera off, then try another enrolled speaker, uncertain speech, several people in view and overlapping speech. Overlapping speakers are not separated. No raw audio, images or biometric features are saved in the new presence tables.
